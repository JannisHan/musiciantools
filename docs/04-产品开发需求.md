# 04 · 产品开发需求（双工具 MVP）

> 本文保留完整候选工具规格；已确认的首发范围、架构、交互与测试接口以 `06-MVP实施决策.md` 为优先依据。首发只实现 BPM/延迟工具，琴弦张力比较器须在数据可行性通过后另行立项。
>
> **技术形态总则**：计算全部在浏览器本地完成，无登录、无付费墙。公开路由预渲染，Cloudflare Worker 仅承担 SSR 回退与匿名白名单事件写入，不接收计算原始输入。

## 1. 技术栈建议（接手机型可优化，但需满足约束）

| 层 | 建议 | 约束 |
|---|---|---|
| 框架 | TanStack Start（锁定依赖版本） | 公开页面必须可预渲染；保留 Worker SSR 回退 |
| 样式 | Tailwind CSS + 项目自有组件 | 移动端优先，不套用通用 SaaS 组件视觉 |
| 部署 | Cloudflare Workers + Static Assets | 使用 `@cloudflare/vite-plugin`，不是 Cloudflare Pages |
| 状态 | 纯前端（useState/URL 参数持久化，可分享状态） | 无后端 |
| 分析 | GSC + Cloudflare Web Analytics + Analytics Engine 白名单事件 | 不保存原始输入或访客标识 |
| 测试 | Vitest + Playwright + 自动化可访问性 + 生产构建 | 公式、关键交互和 SEO 输出必须可回归 |

## 2. 站点结构（sitemap 骨架）

```
/                                        # 首页：首发工具与清晰价值主张
/tools/bpm-delay-calculator/             # MVP：首先发布的 SEO 实验
/tools/string-tension-calculator/        # P1：仅在数据可行性通过后开发
```

候选工具在实际开发并满足独立价值前不得加入 sitemap，也不提前创建空页面。多语言必须先完成当地关键词、文案和联盟可用性验证。

## 3. 工具规格与候选池

实现顺序以状态为准：先开发 3.2 BPM/延迟，再在数据可行性通过后发布 3.4 琴弦张力；其余章节只是候选资料。

### 3.1 品丝布局生成器（fret calculator）— P1 候选

- **slug**：`/tools/fret-calculator/`；首版不为 ukulele/banjo/mandolin/bass 拆分变体页
- **目标词**：`fret calculator`（260/KD 9）、`fret spacing calculator`（110/KD 6）
- **用户场景**：自制琴、维修、改装乐手计算品丝开槽位置
- **核心功能**：
  1. 选择乐器预设（吉他 Fender 25.5"、吉他 Gibson 24.75"、贝斯 34"、尤克里里 Soprano 13"/Concert 15"/Tenor 17"/Baritone 19"、班卓 26.25"、曼陀林 13.875"）或自定义弦长；
  2. 输入品数（默认 24）；
  3. 输出：每品到琴枕距离表 + 品间距表（支持 mm/inch 切换）；
  4. 复制/导出 CSV；如进入开发，差异化验收必须包含带比例校准的 SVG/PDF 或等比例打印模板；
  5. multiscale/fanned fret 仅在完成制琴用户验证后进入后续版本；不提供定义不清的单一“弦枕补偿”开关。
- **公式**：第 n 品到琴枕距离 = 弦长 × (1 − 1/2^(n/12))；等效常量 17.817（弦长英寸 ÷ 17.817 = 第一品距）。**公式需单测覆盖。**
- **页面结构（SEO）**：工具首屏 → H2 公式与原理说明（200-400 字）→ 常见弦长表 → FAQ 区（What is a fret calculator / How to measure scale length / Fret calculator for ukulele...）→ 相关工具内链。
- **UI 要点**：结果表可滚动、行可点选高亮；移动端一屏内完成输入。

### 3.2 BPM/延迟工具（bpm-delay-calculator）— MVP 首先发布

- **slug**：`/tools/bpm-delay-calculator/`
- **目标词**：`bpm to ms`（1000/KD 3）、`delay time calculator`（480/KD 20）；两词由同一页面覆盖
- **用户场景**：设置延迟/混响踏板、DAW 延迟时间、排练现场 tap tempo
- **核心功能**：
  1. BPM ↔ ms 双向换算（输入任一侧即时出另一侧）；
  2. 音符细分表：全音符/二分/四分/八分/十六分、附点八分（×0.75）、三连音八分（×1/3）、附点四分、三十二分等；
  3. **Tap tempo**（点击/空格键测速；最近间隔采用稳健统计，过滤明显异常值，长时间停顿后自动重置，并显示稳定度）——内嵌功能，不单独建页；
  4. 半音/音分变速计算：f₂ = f₁ × 2^(n/12)，BPM 随变速比例换算（DJ/制作场景）；
  5. 预设常见歌曲 BPM（可选，后期）。
- **公式**：quarter note ms = 60000 ÷ BPM；eighth = 30000 ÷ BPM；triplet eighth = 20000 ÷ BPM；dotted eighth = 45000 ÷ BPM；dotted quarter = 90000 ÷ BPM；half = 120000 ÷ BPM；whole = 240000 ÷ BPM。**全部单测。**
- **页面结构**：工具首屏 → 延迟时间表（按 BPM 动态）→ H2 "How to use delay time calculator"（200-400 字）→ FAQ（dotted eighth note delay 等长尾）→ 相关工具内链。
- **UI 要点**：大字显示结果；tap tempo 大按钮（移动端拇指友好）；支持 URL 参数（`?bpm=120`）直达结果（可分享）。

### 3.3 Hz↔音符↔MIDI↔音分转换器 — P2 候选

- **slug**：`/tools/note-frequency-converter/`
- **目标词**：`hz to note`（590/KD 23）、`note frequency calculator`（50）、`midi note number converter`、`cents to hz calculator`（长尾入 FAQ）
- **用户场景**：采样调音、合成器/硬件编程、混音微调
- **核心功能**：
  1. 四向输入：Hz / 音名（A4 格式，含升降号）/ MIDI 编号（0-127）/ 音分偏移；
  2. 任一输入即时输出其余三者 + 与标准音高的音分偏差；
  3. 基准音可调（A4 = 440Hz / 432Hz / 442Hz 等）；
  4. 常用音阶频率表（C4-B4 等，可切换八度）。
- **公式**：MIDI→Hz：f = 440 × 2^((m−69)/12)；Hz→MIDI：m = 69 + 12 × log₂(f/440)（取最近整数音，偏差 cents = 1200 × log₂(f/f_note)）。**单测。**
- **页面结构**：工具首屏 → 公式说明 → 频率表 → FAQ → 内链。
- **UI 要点**：四个输入框同屏互算；音分偏差用绿色（准）/黄色（微偏）/红色（大偏）标注。

### 3.4 琴弦张力比较器 — MVP 同批商业核心

- **slug**：`/tools/string-tension-calculator/`
- **目标词**：`guitar string tension calculator`（1900/KD 31）
- **用户场景**：换规格弦、改变弦长或特殊调弦前，比较当前配置与目标配置的手感和总张力变化
- **核心功能**：
  1. 乐器选择（电吉他/木吉他/贝斯）+ 调弦预设（标准/drop D/DADGAD/半音降等）+ 自定义；
  2. 当前配置与目标配置并排；支持调弦、弦长、单弦规格和混合规格；
  3. 首版规格数据库只采用能够逐项核验 Unit Weight/官方张力表的数据源，优先 D'Addario；不得仅凭线径推测不同结构琴弦的单位重量；
  4. 输出每弦张力（lb/kg）+ 总张力 + 相对当前配置的变化百分比；
  5. 不输出“琴颈安全/不安全”结论，不使用无依据的固定 15% 安全阈值；提供相对变化说明和必要免责声明。
- **公式**（英制）：T = (UW × (2 × L × F)²) / 386.4，其中 UW=单位重量(lb/in)、L=弦长(in)、F=频率(Hz)、T=张力(lbf)。**单测 + 与厂商官方张力表交叉验证。**
- **数据需求**：弦规格数据库（JSON/静态文件）——字段至少包含品牌、产品/SKU、结构、弦序号、直径(in/mm)、单位重量、来源 URL、来源版本/日期、最后核验日期。未经官方资料核验的品牌不进入预设库。
- **页面结构**：工具首屏 → 各品牌套弦数据表（可搜索）→ 张力原理说明 → FAQ → 内链。
- **UI 要点**：选弦可视化（6 根弦图标）；对比模式（两套弦并排）；用中性文案突出相对变化，不以颜色或警告暗示具体乐器结构安全。

### 3.5 音频文件大小计算器 — 当前删除

- **slug**：`/tools/audio-file-size-calculator/`
- **裁决**：与首期吉他设置定位、复访和联盟转化均弱，不为凑主题集群开发；以下公式仅保留为历史候选资料。
- **功能**：采样率 × 位深 × 声道 × 时长 → WAV 大小；MP3/AAC 码率 × 时长 → 压缩格式大小；反向（给定大小算时长）。
- **公式**：WAV bytes = sample_rate × (bit_depth/8) × channels × seconds；压缩格式 bytes = bitrate_kbps × 1000/8 × seconds。**单测。**
- **页面结构**：工具 → 常见配置表（44.1/16 立体声 1 小时 = 635MB 等）→ FAQ → 内链。

### 3.6 音箱阻抗计算器 — P2，需领域专家审核

- **slug**：`/tools/speaker-impedance-calculator/`
- **目标词**：`speaker impedance calculator`（量小，KD 不可测）及变体
- **用户场景**：箱体接线（**算错会烧功放**，安全刚需）
- **核心功能**：
  1. 多喇叭并联/串联/串并联混合 → 总阻抗；
  2. 功放匹配检查：给定功放最小负载（如 4Ω/8Ω）判断是否安全，红色警告；
  3. 功率分配显示（并联时各喇叭承受功率）；
  4. 常见组合预设（2×8Ω 并联=4Ω 等）。
- **公式**：串联 Z=ΣZ；并联 Z=1/Σ(1/Z)；同值 n 个并联 Z=Z/n。**单测 + 安全判断逻辑必须保守（宁可误报不可漏报）。**
- **社区策略**：如进入开发，先按社区版规征求需求和安全边界反馈；社区发布的主要目标是验证与推荐流量，不预先计作 SEO 外链。
- **免责声明**：页面显著位置注明"接线错误可能损坏设备，请以功放说明书为准"（信任与合规双赢）。

### 3.7 效果器电源兼容规划器 — P1 调研候选

- **slug**：`/tools/pedalboard-power-calculator/`
- **目标词**：`pedalboard power calculator`（量不可测）及变体
- **用户场景**：拼效果器板算总耗电（mA），判断电源适配性
- **核心功能**：
  1. 单块数据库（品牌/型号/电压/电流 mA，含 AC/DC 标识）——支持搜索添加；
  2. 按单个电源输出校验电压、AC/DC、极性、最大电流、接口和隔离情况；总 mA 只能作为辅助信息，不能替代逐输出兼容判断；
  3. 手动添加自定义单块。
- **数据需求**：常见单块 mA 数据库（Strymon/ Boss/ Electro-Harmonix 等公开手册数据），JSON 静态文件，来源标注。
- **社区策略**：先到效果器社区验证逐输出兼容工作流与数据准确性，不以获取外链作为开发依据。
- **页面结构**：工具 → 常见单块耗电表（SEO 长尾载体）→ FAQ → 内链。

## 4. SEO 全局规范（所有页面必须遵守）

1. **标题**：每页唯一、准确描述用户任务并自然包含主要查询；60 字符仅作避免冗长的内部参考，不是搜索引擎硬限制；
2. **Meta Description**：每页唯一，说明具体输入、结果和用户收益；155 字符仅作展示参考；
3. **H1 唯一且含目标词**；H2/H3 语义分层；
4. **结构化数据**：只标注页面真实可见的信息。可使用 WebApplication/SoftwareApplication 语义标记，但不得伪造评分或评论，也不以富结果作为验收目标；
5. **问答区**：只回答真实用户问题，不设每页条数配额；普通工具站不以 FAQPage 富结果为目标；
6. **内链**：MVP 每个工具页至少链接首页和另一个确实相关的工具/方法页；后续只增加有用户路径关系的自然内链；
7. **首屏原则**：工具在首屏（≤ 1 屏可见），解释性文字在工具下方——工具站不写"先看 2000 字再用"；
8. **公式/数据来源标注**：每个工具页注明公式、数据来源、版本和限制，用可核验信息建立信任；
9. **性能**：移动端目标 LCP < 2.5s、INP < 200ms、CLS < 0.1；Lighthouse ≥ 90 仅作为实验室门槛，不能替代真实用户数据；
10. **多语言（二期）**：i18n + hreflang，URL 前缀式（/es/），不建子域；
11. **sitemap.xml + robots.txt** 必配；所有带计算状态参数的分享 URL canonical 到无参数工具主页，sitemap 与站内链接只使用干净 URL；
12. **商业链接**：联盟链接使用 `rel="sponsored"` 并提供可见披露；接入 AdSense/GA4 时按目标地区实现适用的同意管理。

## 5. 开发阶段与验收标准

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| MVP-A | 站点骨架 + BPM/延迟工具 + 方法/来源与联盟披露 | ①公式单测通过；②Core Web Vitals 目标和 SEO 规范落实；③干净 canonical 与可分享状态兼容；④核心行为事件可观测 |
| MVP-B | 完成数据可行性后发布琴弦张力比较器 | ①张力结果与官方数据交叉验证；②每条预设数据可追溯；③当前/目标配置对比可分享；④不输出设备安全结论 |
| P1 决策门 | 根据 GSC 查询、计算完成、分享/导出和联盟点击选择品丝布局或效果器电源规划 | 不因低 KD 或页面数量目标自动开发；必须补齐用户与 SERP 证据 |
| P2 | Hz/MIDI、阻抗等候选 | 重新验证搜索机会；涉及设备安全的工具须经领域专家审核 |
| 多语言 | 仅对已在英文版验证成功的工具进行当地关键词研究和人工本地化 | hreflang 双向完整、页面主体真正翻译、当地联盟路径可用 |

## 6. 给接手机型的开发建议（非强制）

- 先做一个"工具页模板"（工具区/说明区/真实问答/来源/内链），但模板复用不能代替每个工具的独立用户价值；
- 每个工具的公式单独成模块（lib/），与 UI 解耦，保证单测容易写、后期可复用；
- 交互状态写入 URL 参数（如 `?bpm=120&division=dotted-eighth`），实现"分享即保存"；
- MVP 不上后端；弦规格使用带来源元数据的静态文件，并建立人工核验流程；
- GA4 与 GSC 在首个工具上线当天接入，之后每周看一次"性能-查询"报表挖新词（见 `02-关键词调研与裁决.md` 第 5 节）。
